# 模型 —— 接入一个 AI 服务商

应用自己不带 AI。你提供一个服务商的密钥，请求从你的浏览器直接发给他们。中间没有任何
转手，localmd 也不收任何费用。

在 **设置 → 模型** 里配置。

## 添加一个模型

点 **添加模型**，选服务商，粘贴 API key，填模型名。其余的会自动帮你填好。

模型名下面有一排勾选框 **这个模型能做什么**：对话、能看图、能生图。它们会按你选的服
务商预先勾好，但那只是一个起点的猜测 —— 服务商这个信息本来就说明不了它旗下某一个模
型的事，对自定义接口更是什么都说明不了。改这里，下面的角色就跟着变。

Anthropic、OpenAI、Google、DeepSeek、智谱、通义、xAI，以及任何 OpenAI 兼容的接口都
可以——包括跑在你自己机器上的模型（Ollama 之类）。你可以加好几个，随时切换。

密钥或模型名填错了，第一次发消息时聊天区会告诉你。

## 思考强度

有些模型回答前会先推理一番。那段推理常常是结果里最有价值的部分 —— 也常常远远长过
问题本身值得的篇幅。

每个模型的 API key 旁边都有一个 **思考强度**，从「关闭」到「很高」。回复里塞满了你
并不需要的斟酌时，就把它调低；碰上要分好几步走的活儿（比如整理一整个文件夹、现造一
个工具），就调高。留在 **默认** 就由服务商替你决定 —— 而有些服务商替你挑的是最重的
那档：比如 GLM-5.3 系列永远思考，默认还是最深的强度。要是模型斟酌的时间远远长过问
题本身值得的，就别留在默认 —— 明确选一档，从「低」开始试。

它是一个设置，不是每家一个：应用会把它翻译成各家对同一件事的叫法 —— 只能尽力而为，
因为各家的档位对不齐。本来就不怎么推理的模型直接忽略它；某家没有的档位会退回那家自
己的默认值，而「关闭」是这种档位的情况比你想的常见 —— 不是每个模型都肯不思考。少数
接口则会干脆拒收这个请求 —— 真发生了聊天区会告诉你。

两个方向都有代价。思考多了，回答更慢、账单更大；完全不思考，回答可能更差。

## 三个角色

列表下面，每个角色指向你的某一个模型：

- **主模型** —— 负责对话和干活。只有这个是必须配的。
- **视觉** —— 需要看图片时用。
- **图像生成** —— 可选。配上之后助手就能生成图片，直接存进你的文件夹。

每个列表都把你为这件事勾过的模型排在前面。其余的仍然在，收在 **未标记为可做这件事**
下面 —— 选中其中一个，会问你要不要顺手勾上，因为那些勾同样只是你的判断，而一个把你
想要的模型藏起来的列表，比一个多问一句的列表更糟。

生图模型不是对话模型。把它设成主模型是这里最常见的走错方式：之后每一条消息都会发到
一个只会画画的地址上，再以一个关于地址的报错回来。主模型要给对话模型，会画的那个交
给 **图像生成** 角色。

## 你需要单独配视觉模型吗

- 你的模型已经勾了 **能看图**？那就不需要 —— 把视觉角色指向同一个模型，或者它本来就
  是主模型的话留空也行。
- 用的是纯文本模型（比如 deepseek-v4-flash）？把视觉角色指向另一个能看图的模型，需
  要的时候助手会去调用它。

纯文本模型没有配视觉角色，它就是看不了图 —— 而且它会明说，不会照着文件名瞎猜。

## 该选哪个

当下任何一个主流模型都能用。更强的模型在多步骤指令上更靠谱，做那些琐碎活儿（比如
现造一个新工具）也更稳；便宜的模型拿来搜索、总结、归档完全够用。

主模型随时可以换，做到一半换也没关系。最快的方式是点输入框下面的模型名：已配置的模型
会在上方弹出来供你挑选。它的排序和上面角色列表完全一致 —— 勾了「对话」的排在前面，其
余的归到 **未标记为可做这件事** 下面，选到没标记的会先问你一句 —— 所以生图模型不会因
为一次手滑就变成你的主模型。菜单最后一行通往设置。

模型名旁边那只眼睛是视觉角色的同一个入口：它显示现在有没有东西能看图，点它就是选由哪
个模型来看。第一项是 **未配置**，留给主模型本身就能看图的情况。

## 花费

按你的服务商的价格，由他们计费。应用在设计上让每次请求里重复的那部分保持完全一致，
因为所有服务商对重复前缀的收费都远低于新内容 —— 所以一段很长的对话，花的钱比它的
长度看起来要少得多。

把鼠标停在输入框下方的 token 计数上，能看到这次对话用掉了多少。
