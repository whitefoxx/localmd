# 模型 —— 接入一个 AI 服务商

应用自己不带 AI。你提供一个服务商的密钥，请求从你的浏览器直接发给他们。中间没有任何
转手，localmd 也不收任何费用。

在 **设置 → 模型** 里配置。

## 添加一个模型

点 **添加模型**，选服务商，粘贴 API key，填模型名。其余的会自动帮你填好。

Anthropic、OpenAI、Google、DeepSeek、智谱、通义、xAI，以及任何 OpenAI 兼容的接口都
可以——包括跑在你自己机器上的模型（Ollama 之类）。你可以加好几个，随时切换。

密钥或模型名填错了，第一次发消息时聊天区会告诉你。

## 思考强度

有些模型回答前会先推理一番。那段推理常常是结果里最有价值的部分 —— 也常常远远长过
问题本身值得的篇幅。

每个模型的 API key 旁边都有一个 **思考强度**，从「关闭」到「很高」。回复里塞满了你
并不需要的斟酌时，就把它调低；碰上要分好几步走的活儿（比如整理一整个文件夹、现造一
个工具），就调高。留在 **默认** 就由服务商替你决定 —— 你不去碰它的话，现在就是这个
行为。

它是一个设置，不是每家一个：应用会把它翻译成各家对同一件事的叫法。本来就不怎么推理
的模型直接忽略它，少数接口则会干脆拒收这个请求 —— 真发生了聊天区会告诉你。

两个方向都有代价。思考多了，回答更慢、账单更大；完全不思考，回答可能更差。

## 三个角色

列表下面，每个角色指向你的某一个模型：

- **主模型** —— 负责对话和干活。只有这个是必须配的。
- **视觉** —— 需要看图片时用。
- **图像生成** —— 可选。配上之后助手就能生成图片，直接存进你的文件夹。

## 你需要单独配视觉模型吗

- 用 **Claude**？不需要，它自己就能看图。
- 用的模型本来就懂图片（GPT-4o、qwen-vl、glm-4v）？把视觉角色指向同一个模型即可。
- 用的是纯文本模型（比如 deepseek-v4-flash）？把视觉角色指向另一个能看图的模型，需
  要的时候助手会去调用它。

纯文本模型没有配视觉角色，它就是看不了图 —— 而且它会明说，不会照着文件名瞎猜。

## 该选哪个

当下任何一个主流模型都能用。更强的模型在多步骤指令上更靠谱，做那些琐碎活儿（比如
现造一个新工具）也更稳；便宜的模型拿来搜索、总结、归档完全够用。

主模型随时可以换，做到一半换也没关系。

## 花费

按你的服务商的价格，由他们计费。应用在设计上让每次请求里重复的那部分保持完全一致，
因为所有服务商对重复前缀的收费都远低于新内容 —— 所以一段很长的对话，花的钱比它的
长度看起来要少得多。

把鼠标停在输入框下方的 token 计数上，能看到这次会话用掉了多少。
