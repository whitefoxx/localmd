# Skill —— 把一套做法存下来

Skill 就是你摸索出来一次的工作流，写下来之后助手每次都照着同样的方式做。「我怎么归档
一篇论文」「我怎么准备每周回顾」「我们团队的会议纪要什么格式」。

它就是你文件夹里的一个普通 Markdown 文件，不是程序。

## 怎么做一个

最省事的办法：助手刚按你满意的方式做完一件事，你说 **「把刚才那套存成一个 skill」**，
它就会把文件写好。

文件在 `.agents/skills/<名字>/SKILL.md`，顶部是名字和一行描述，下面是具体步骤。你可以
像改任何文件一样改它。

## 怎么用

在输入框里打 `/` 然后选。或者直接描述任务 —— 助手能看到每个 skill 的那一行摘要，匹配
上了就会把完整内容读进来。

新开一个对话时，输入框上方还会把最前面几个 skill 摆成按钮；旁边的 ▲ 打开完整列表。

那行摘要很关键：**决定要不要用这个 skill 时，它只看得到这一行**。「把论文归档到
raw/papers 并生成摘要页」比「论文相关」这种写法有用得多。

## 这个 skill 是给谁用的

默认两边都给：它既在斜杠菜单里，助手也可以自己判断该不该用。但有些 skill 只适合其中
一边 —— 你每周五手动过一遍的检查清单，助手不该自作主张地开始；而它默默照着做的例行
步骤，也没必要占着你的菜单。

在文件顶部加一行 `invocation` 就能指定：

```
---
name: weekly-review
description: 我的周五收尾
invocation: user
---
```

`user` 表示只有你能启动，`model` 表示只有助手能。不写这一行就是两边都可以。

这么做是有实际好处的：助手每次回复开始时，都会被告知所有它可能用到的 skill，所以一个
只有你会用的工作流，每次回复都在花一点点钱。标成 `user` 就把它从那份清单里拿掉了，但
不影响它留在你的菜单里。标成 `model` 的 skill 你照样可以手打 `/名字` 调用 —— 这个设置
决定的是**默认提供什么**，不是允许什么。

## 什么样的 skill 才有价值

写下你**学到的东西**，而不是工具本身已经说明的东西。

一个只罗列工具名字的 skill 毫无价值 —— 那些助手本来就知道。而一个记着「这个接口返回的
时长单位是秒不是分钟」或者「记得去附录里找资助声明」的 skill，每次都能省下真金白银的
功夫。

## Skill 会跟着走

它们存在你的文件夹里，所以会随 git 一起走。分享一个知识库，也就把配套的做法一起
分享了。

应用还自带几个 skill，你不用装。有的是关于应用本身的 —— 比如「接入一个新服务」；有
一个是关于你笔记的：输入 **`/ingest`**，助手就会把你加进来、但还没有任何页面写到过的
材料整理成页面，并且按你文件夹原本的结构来放。你自己同名的 skill 优先级更高。
