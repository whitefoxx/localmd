# 你的文件夹是怎么组织的

你的知识库是一个装着 Markdown 文件的文件夹。格式就这么简单。你可以用任何编辑器打开、
用任何工具同步、随便重新整理 —— 应用开着的时候也行。

## 你的结构说了算

对一个全新的空文件夹，应用会提供一套初始结构：

- **`raw/`** —— 你收集来的材料：论文、文章、图片、书、存下来的对话
- **`wiki/`** —— 你自己写的页面

这是给需要的人的一个建议，不是规矩。**如果你打开的是一个已经整理好的文件夹，应用
不会去动它**，助手会按**你的**结构来归置新东西 —— 用你的文件夹名字、你的命名习惯。

把文件拖进工作区，它会按类型归到 `raw/` 下面。如果文件夹里没有 `raw/`，就落到
`inbox/` —— 门口的地垫，不是家。

但归位不等于读过。拖进文件之后，消息框上方会出现一行 ——「已归档 3 个，还没读」——
右边一个按钮开始读，一个 × 表示先不读。你不点它就什么都不会发生，而且关掉它没有任何
代价：东西照样归好了，你哪天想起来助手还是找得到。

这是有意的。读一摞材料要花模型时间、要往你的文件夹里写新页面，这两件事都不该因为
「有个文件被拖进了窗口」就自动开始。你也可以随时直接输入 **`/ingest`**。两种方式都
一样：助手会挑出你加进来、还没有任何页面提到过的材料，逐个读完（PDF 和 EPUB 会顺手
建好索引），写进你的页面，然后告诉你做了什么、留下了什么。它从不改动源文件本身；再跑
一次也只会处理新增的部分。

附件是另一回事。你粘进聊天框的截图、在那里附上的文件，是**递给**助手的东西，不是你在
归档的东西，所以它们会进一个叫 `.tmp` 的暂存目录。这个目录不出现在文件树里、不进搜索、
也不进 git，里面的东西随时可能被清掉。点一下附件就能像别的文件一样在文件视图里打开；
如果哪一个值得留下，让助手把它挪到真正该待的地方。

## 告诉助手你的文件夹怎么用

文件夹根目录下一个叫 **`AGENTS.md`** 的文件，用来描述你的约定 —— 什么放哪、怎么命名、
任何它该知道的事。助手每次对话开始都会读它。

你不用自己写。让助手看一遍你的文件夹然后写一份，它会照着你**实际有的**来写，而不是
硬塞给你一套。

只有一样它替你写不了，而且值得你自己花两行字：**这个知识库是干什么的。**你想让它回答
哪些问题、你朝哪个方向在读、你不关心什么。文件夹能告诉助手一页该放哪；但一份材料里哪
些部分值得留下来，只有你能说 —— 同一篇论文，冲着方法读和冲着结论读，记下来的东西是
不一样的。新建文件夹的 `AGENTS.md` 里有一节空的 **Purpose** 在等这句话。你留空，它也
不会自己编一个填进去。

## 没有任何强制

这里的每一条约定 —— 目录结构、页面格式、链接方式 —— 都是助手会遵守也会建议的做法，
没有一条是能拒绝一个文件的硬规则。随便手改、随便移动、随便删。不会出错，也不会有东西
反复烦你。

## 页面之间的链接

写 `[[页面名]]` 就能链到另一个页面 —— 名字不带 `.md`。链接是让一个页面不至于变成孤岛
的关键，关系图也是靠它。

页面顶部还可以带一个 `type:`（`concept`、`source`、`person` 之类），你觉得有用就用。
它是自由填写的，没有固定清单。

## log —— 那些不是一页笔记的东西

读出来的东西里，有一部分不适合作为一页。两篇笔记结论打架；某个数字后面没有出处；
一个问题悬在那里。

这些进 **`log.md`**，写成带日期、点名相关页面的条目：

```
## 2026-03-01 —— [[chain-of-thought]] 和 [[prompting]] 对阈值的说法不一致
一个说 10B 参数，一个说 100B。未解决。
```

扫描发现问题时，助手会提出把它记下来，而不是在一段你随手就会关掉的对话里说一次。
它不会偷偷改掉其中一页把矛盾抹平 —— 哪边对，是你说了算。

新建的文件夹会带一个空的 log，空着才是新知识库的正常状态；你不想要就删掉它，没有任何
东西会把它放回来。如果你的文件夹本来就有自己的做法，助手跟着你的来。

那个日期是有用的：下面的体检能告诉你某条目值得重看一遍 —— 因为它点名的页面在你写下
它之后被改过。它永远不会替你判定一条已经解决，只会说「它下面有东西动了」。

## 给知识库做个体检

左侧栏的**脉搏图标**只列两件值得点开的事：链向不存在页面的断链，和没有任何页面链
向的孤儿页。

让助手做一次体检，它会把同一套检查跑全。除上面两项外，它还会报告：几乎是空的页面、
从索引出发导航不到的页面、没有 frontmatter 的页面、你加进来但从没有任何一页提到过的
文件、指向已经不在的文档的引用、写完之后所引文档又被改过的页面、点名的页面后来又被改
过的 log 条目，以及同一个词的两种写法（`machine-learning` 和 `Machine Learning`）。

最后这条值得多说一句，因为它比的是时间戳而不是含义：一个只是被重新保存过、被同步
客户端重新下载过、或者刚刚被 git 检出的文件，看起来和被重写过的一模一样。动手之前
先拿页面对着文档读一遍 —— 也永远不要让助手凭记忆重写一页来把这条警告消掉。

这些都很快、免费，而且一页内容都不用读 —— 所以它对自己的局限也很诚实。它是一份「你
也许想看一眼」的清单，不是一份错误清单：留着下个月再读的 PDF、一个标签的两种写法，
那是你的自由，这里的任何一条都不会替你改掉。更深的问题 —— 「这几页之间有没有互相矛
盾？」—— 确实需要助手去读你的内容，所以直接问它，它会先跟你商量一个范围，而不是把整
个库读一遍。
