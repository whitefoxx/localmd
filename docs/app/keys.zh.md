# API 密钥与隐私

有些服务需要一个密钥来证明请求是你发的。你的密钥存在你自己的浏览器里，**永远不会
给到助手**。

## 这是怎么做到的

工具里面存的不是密钥，而是一个**名字** —— 一个像 `{{secret:weread_api_key}}` 这样的
占位符。真正的值是在最后一刻、请求真正发出去的时候才填进去的，也仅限那一刻。

所以助手可以读写这个占位符，却从头到尾不知道它代表什么。实际效果是它能真正帮上忙 ——
「这个工具需要一个叫 `weread_api_key` 的密钥，你可以在这里申请，现在这一栏是空的」——
同时它压根不处在能泄露密钥的位置上。

## 怎么把密钥给它

助手需要密钥时，不会让你粘到聊天框里。而是会弹出一个小表单，你直接填进应用里。值进
浏览器存储，助手只被告知「保存了一个值」。

**绝对不要把密钥粘进聊天输入框。** 你在那里打的字是真的会发给模型的。如果不小心发了，
删掉那条消息并去把密钥重置掉。

你也可以随时自己填：**设置 → 工具 → 密钥**。这里只列出你已装工具真正要用的密钥，
所以不会又长又乱。

## 唯一需要留心的一点

密钥名是一份所有工具共用的扁平列表。任何工具只要按一个你已经有的名字来要，就能拿到
那个值 —— 不管这个工具是往哪个服务发请求。

这一点在工具来自外部时才要紧，比如跟着别人分享的知识库文件夹一起来的。为此有两道
保险：

- 每个密钥下面，应用会列出有哪些工具会读它。
- 你确认文件夹自带的工具时，如果它们想用你已有的密钥，会专门提醒，并且告诉你数据会
  发到哪里去。

## 密钥存在哪

存在这个站点在你浏览器里的本地存储中，和你的模型服务商密钥、GitHub token 放在一起。
具体来说：

- 它们**不在**你的知识库文件夹里，所以永远不会被提交到 git，也不会跟着你分享出去的
  文件夹走。
- 它们**不在**我们的任何服务器上，因为压根没有服务器。
- 清除浏览器里这个站点的数据会**把它们删掉**。你的笔记不受影响 —— 那是硬盘上的文件。
